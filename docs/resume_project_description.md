# Resume project description

- Built a Python/Pandas data pipeline for 12 official HMRC monthly disclosures containing 12,973 published payment lines, preserving source hashes and row lineage through transactional PostgreSQL ingestion and Decimal reconciliation.
- Implemented parameterized PostgreSQL analytics with window-function supplier ranking, Pareto analysis and concentration metrics, plus four explainable procurement-review detectors surfaced in a five-page Streamlit/Plotly application.
- Developed a reusable Decimal financial scenario engine with sensitivity analysis, validated JSON interchange, formula-driven Excel exports and editable five-slide executive PowerPoint generation, supported by automated unit/integration tests and browser/artifact verification.

## Interview explanation

I built ProcureIQ to turn public payment disclosures into traceable procurement investigation questions. The engineering challenge was preserving the original evidence while handling credits, repeated identifiers, supplier aliases and revised source files. I used PostgreSQL functions for filtered analytics and independent Decimal calculations to verify the outputs. The application separates observed expenditure from review hypotheses and hypothetical financial benefits, so an opportunity score never becomes an assumed saving. I tested the data pipeline, analytical formulas, state transitions and exports, then inspected the running application and rendered presentation. It is a local portfolio project, not a deployed procurement system, and I do not claim realized savings or business adoption.
